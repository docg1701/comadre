## Deferred from: code review of story-2-3 (2026-04-18)

- **AC15 two-snapshot-write interval assertion + NFR7 ≤2 ms p99 benchmark.** Single-write is verified via `test_start_returns_task_and_fires_once`; the AC15 wording asks for two writes across a 30s window and a 10 ms loop-block budget — neither is asserted. NFR7 budget is design-by-construction (O(1) dict ops, no request-path I/O) but not benchmarked. Fold into `scripts/bench_rate_limit.py` follow-up. [`tests/test_counters.py:231-241`]
- **AC19 PII test narrower than wording.** Current test asserts only `cmdr_live_` and 64-hex absence; AC19 lists customer name, email, and CPF/CNPJ 11–14 digit runs. Coverage-only — snapshot has no writer path that could leak those by construction (only `schema_version`, `written_at`, `process_uptime_seconds`, `auth_cache.snapshot()` ints, and `per_key[key_id]` int counters + ISO `last_activity_at`). Add a combined regex assertion on the next test-hygiene pass. [`tests/test_counters.py:169-180`]
- **Unbounded `window_hits` deque at high `rate_limit_rpm`.** At 10 000 rpm, a single key's deque carries ~600 K floats (~4.8 MB) before pruning. Today's rpm cap is 10 000 (Story 2.2) and no customer is anywhere near it; revisit if higher-RPM tiers are introduced. [`src/comadre/counters.py:58, 104`]
- **`stop_snapshot_writer` has no timeout.** If the final `asyncio.to_thread` hangs on NFS / stuck mount, container shutdown stalls indefinitely. Add `asyncio.wait_for(..., timeout=5)` around the inner write once NFS-backed deployments become a concern. [`src/comadre/counters.py:197`]
- **Disk-full orphan `.tmp` file.** `tmp.write_text(...)` followed by `tmp.replace(...)` can leave a partial `.tmp` if the write fails with `OSError`. The next successful write truncates it via `write_text`, so persistence is bounded, but a permanently-full disk leaves the orphan. Wrap with `try: write + replace except OSError: tmp.unlink(missing_ok=True); raise`. [`src/comadre/counters.py:247-256`]
- **`TestPeakAndAverage` monkeypatch ordering.** `monkeypatch(time.monotonic)` applied after `RequestCounters(...)` construction means `process_start` captures the real monotonic clock and `process_uptime_seconds` in the snapshot can be 0 or negative depending on fixture order. Test-only latent flake. Fix by constructing `rc` after the patch, or set `rc.process_start` explicitly. [`tests/test_counters.py::TestPeakAndAverage`]
- **`written_at` parser only catches `ValueError`.** Today's writer always emits `Z`-suffixed ISO, so the `replace("Z","+00:00")` + `fromisoformat` path works. A future writer that emits naive-datetime strings would return a naive datetime; the subsequent `datetime.now(UTC) - written` then raises `TypeError`, not caught. Broaden to `(ValueError, TypeError)`. [`src/comadre/keys/cli/commands/customers.py:434-437`, `src/comadre/keys/cli/commands/system.py:89-97`]
- **JSON `snapshot_available: true` with missing telemetry fields.** `cache-status --format json` returns `snapshot_available: true` when the file parses, but omits `entries` / `hits` / `misses` / `hit_rate` when `auth_cache` is absent or not a dict. Operator automation keying off `snapshot_available` could trip over missing telemetry keys. Either include telemetry fields as `null` or flip `snapshot_available` to `false` when `auth_cache` is unusable. [`src/comadre/keys/cli/commands/system.py:187-205`]

## Deferred from: code review of story-2-2 second pass (2026-04-18)

- **`/health` shape-valid-random DoS — mitigate at Caddy.** The bearer shape-check short-circuit blocks garbage tokens but lets shape-valid uniform-random tokens (`cmdr_live_` + 43 valid base64url chars) through to `lookup_key_auth`, which serializes on the single SQLite connection. Under sustained spray, CLI mutations can hit `SQLITE_BUSY`. Operator decision 2026-04-18: add IP-based rate limit on unauthenticated `/health` via Caddy's `rate_limit` directive (or CrowdSec) rather than reintroduce an app-layer limit. `/health` is cheap + idempotent so the Caddy cap can be loose (e.g., 60/min/IP). Touch points for the Caddy config: `deploy/caddy/Caddyfile` — wrap the `handle` for `/health` in a `rate_limit` block. Rationale: keeps the app layer library-simple (only per-key via `limits`), pushes infra concerns to infra. [`src/comadre/main.py:300-303`, `src/comadre/keys/auth.py:79-93`, `deploy/caddy/Caddyfile`]
- **`get_window_stats` not strictly atomic with `.hit()`.** `MemoryStorage.acquire_entry` holds the per-key `asyncio.Lock` only for `.hit()`; `get_moving_window` (read path) takes no lock. Under concurrent load, `X-RateLimit-Remaining` and `X-RateLimit-Reset` can drift from the actual consumed state. Retry semantics (the `Retry-After` floor) remain correct; impact is header accuracy only. Library-level mitigation — wrap both calls in a shared per-key lock or accept documented drift. [`src/comadre/rate_limit.py:108-109`]
- **Cross-mount sentinel invalidation silently fails.** If CLI runs on the host and API in a container with a non-bind-mount copy of the DB directory, sentinel touches don't propagate and revoked keys keep authenticating for up to the 60s cache TTL. Documented in `docs/troubleshooting.md:211-213` but no runtime guard or startup self-check. Add a startup probe: API writes a known sentinel value, asserts the CLI path reads it back, logs WARN on mismatch. [`src/comadre/keys/db.py:163-183`]
- **Sentinel invalidation via mtime is vulnerable to coarse-mtime filesystems and same-tick collisions.** On FAT32 / NFS with `attrcache` / certain overlay filesystems, two mutations within the same second share an mtime and the cache never flushes. Even on ext4 (ns precision), two touches within the same ns tick collide. Move to content-based signaling (write a monotonic counter to the sentinel file, compare content not mtime) in a hardening pass. [`src/comadre/keys/cache.py:72-79`]
- **Pydantic `ValidationError` for `KEY_REGISTRY_ENCRYPTION_KEY` leaks raw input in error repr.** If the lifespan crashes on a malformed Fernet key, the bad key value appears in the Docker / systemd log stream via pydantic's `input_value` field. Defensive mitigation: sanitize the validator error message (truncate or replace `input_value`) or catch + re-raise from the `get_settings()` call site with a redacted message. Belongs with broader secret-handling hardening pass. [`src/comadre/config.py`]

## Deferred from: code review of story-1-4 (2026-04-17)

- **`ShowTarget.value` typing forces `cast(...)` at every call site.** The discriminated-union `value: CustomerDetailRow | KeyDetailRow | list[KeyDetailRow] | None` requires every reader to `cast(...)` the variant out, even after narrowing on `result.kind`. Mypy can't bind the variants to the discriminator without `match`-with-variant-classes or a `TypeGuard` shim. Spec §Task 8.2 explicitly accepts this shape, but a future cleanup could split into per-kind dataclasses with a `Union[…]` alias. - **`list_audit_events` IN-clause unbounded against `SQLITE_MAX_VARIABLE_NUMBER`.** `target_ids` is interpolated into a positional-`?` list with no chunking. Modern SQLite caps at 32k vars by default so the surface is theoretical today, but a customer that ever accumulates hundreds of keys + a bulk audit-tail query would silently approach the cap. Address with chunked OR-merging or a temp-table join when a high-volume operator emerges. [`src/comadre/keys/db.py`]
- **Rich markup injection via stored `name` / `notes` / `customer_name` in DetailPanel bodies.** Pre-existing pattern from Story 1.2/1.3 panels — stored data is interpolated into Panel content with `markup=True` (the rich default). [`src/comadre/keys/cli/output.py`]
