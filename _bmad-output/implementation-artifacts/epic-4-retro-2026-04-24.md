## 2. Successes

1. **100% delivery on a security-and-LGPD epic with zero schema migrations.** The tombstone-as-zero-length-BLOB pattern (Story 4.1) sidestepped a v002 migration. Every NOT-NULL constraint stayed honored.
2. **3-layer adversarial code review caught real bugs in every story.** Examples in Story 4.6 alone: `update-customer --name` flag does not exist (HIGH); Caddy returns 502 not "cached 401s" on `tts-service` stop (HIGH); `docker compose exec` missing `-T` silently corrupts `.env` writes during key rotation (MED, sidecar-fixed in `deployment-guide.md`).
3. **Marker-file design pattern compounded.** Story 3.4 introduced `{db}.cron-installed`; Story 4.3 reused the shape for `{db}.backup-cron-installed`; Story 4.4 closed the consumer loop in `comadre-keys health`. Three stories, one design.
4. **Defense-in-depth where it mattered.** `bootstrap.yml` chmod + Python `_chmod_0600` at connection time. `ansible-playbook health.yml` assertions + in-container `comadre-keys health`. `_FORBIDDEN_DETAIL_KEYS` audit-payload guard in 4.2.
5. **The 4.5 umbrella split was the right call.** Splitting Story 4.5 into 4.5a–g per the implementation-readiness-report shipped 7 focused CI checks instead of one mega-PR. Each sub-story had a clean review cycle.
6. **`CLAUDE.md` "Non-Obvious Gotchas" earned its keep.** ~12 new entries this epic, every one tied to a real "do not fix this" or "this is load-bearing" insight (zero-length BLOB tombstones; backup tarball naming contract; `BACKUP_PASSPHRASE` empty-at-boot rationale; `ansible-playbook health.yml` is the trustworthy boolean).

## 3. Challenges

1. **Deferred-work accumulation discipline outpaced consumption.** ~60 entries since Story 1.1, none consumed. The discipline is excellent; the triage cadence is missing. Today's directive closes that gap.
2. **Cross-cutting helpers never consolidated.** `_allowlisted_lines` is duplicated across 4.5c/4.5f/4.5g (3 near-identical AST/regex scanners). `_seed_customer_and_key` is forked across ≥7 test files (Story 1.6 already flagged "the last tolerable threshold"; 1.6 added three more). `load_settings_and_tz` is loose-typed and forces `cast()` at every CLI call site (>8 suppressions).
3. **Settings monolith never split.** Story 1.2 manual-test surfaced "comadre-keys CLI requires TTS-side config it does not need." Flagged for Epic 2 boundary; never paid. Carries forward as a first-run UX wart.
4. **Caddy 404/405 header gap.** Discovered during 4.5a, deferred there, resurfaced during 4.5a code review. `file_server` in Caddy 2-alpine writes 404/405 directly via its internal error path before site-block `header { … }` middleware runs, so 404/405 responses ship without the 6 security headers and without `-Server`/`-Via`. The fix (`handle_errors` block re-applying the 6 headers) is empirically tested but not landed because it was outside 4.5a's "pure test infra + CI wiring" scope.
5. **Non-regression CI does not cover `Caddyfile-no-landing`.** Two Caddyfiles drift only on code review. The whole point of 4.5a–g is to remove that vector.
6. **Backup crypto choices are on the older floor.** PBKDF2 at openssl-3 default 10K (vs OWASP-2023 600K). AES-256-CBC unauthenticated (vs AES-256-GCM). Spec chose portability; the directive now says: pay it.

## 4. Insights

- The 3-layer adversarial review cycle (Blind Hunter + Edge Case Hunter + Acceptance Auditor) found real defects every time. **Keep this for Epic 5.**
- The `# scan-allow:` convention is correct in spirit but the token is shared verbatim across 4.5c/4.5f/4.5g — a single comment can silence two scans by accident. Namespace it.
